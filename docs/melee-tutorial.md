# 近戰訓練課程（作戰室的模擬艙）

教不懂的玩家把 `docs/melee-combo-design.md` 的近戰系統學會：8 課、循序漸進，玩過就會。課程資料在 `src/data/tutorial.js`，流程與畫面在 `src/game/tutorial.js`。

## 定案（2026-10-27）

- **入口**：作戰室的「模擬器」最上面一區「近戰訓練課程」，照順序開放（完成上一課才開下一課）。只有單人。
- **武器**：每一課開始前選近戰武器：脈衝刀、光束大劍、破碎爪、打樁機、空手（拳擊）。教學中都能用，不必先買；招式名稱與說明跟著武器變（`tagName`）。左手固定霰彈槍（第 5 課的近戰接射擊、射擊接近戰）；左右手交替（選修）時左手換成第二把近戰武器；盾擊與綜合練習時肩上裝脈衝盾。
- **獎勵**：第 1～7 課第一次完成給 COAM（2,000～6,000，合計 28,000）；第 8 課結業從脈衝刀、破碎爪、打樁機挑一把免費拿（都有了改給 COAM 20,000）。光束大劍是教官考核的獎品，不放進來。
- **引導**：第一次進作戰室時教官的通訊建議先上第 1 課（只一次）；上完第 1 課以前作戰室的模擬器按鈕有紅點、場景裡的模擬艙標籤寫「近戰訓練 第 1 課」。
- **假人**依課程進度變強（`TUT_LV`）：0 靜止、1 走動、2 閃避（靠近時 QB 拉開）、3 反擊（你停手時紅光預警後揮刀或開槍）、4 進攻（主動出招）。出招的預警 0.9 秒，預警與揮刀中不會被硬直打斷（才練得到彈刀）。

## 教學的原則

1. 一次只教一件事；前一個練熟（成功 2～3 次）才開下一個。
2. 先看、再做、再重複：每個練習先 0.5 倍速示範（自己的機體照腳本的虛擬輸入動作，按鍵順序就是你要按的），再換你做。
3. 時機看得見：要抓時機的練習有時機條（`bar`），綠色區＝該按的時候；剛開始放慢（`speeds`），成功幾次後回到正常速度。
4. 失敗時說原因（太早、太晚、揮空、方向不對、QB 太早……），同一步失敗 3 次提示更具體，5 次提議再看示範並放慢一級。
5. 按鍵提示跟著裝置（鍵盤、手把、觸控）與自訂按鍵；方向派生的方向就是按鍵本身（上＝前、下＝後、左右＝側），畫面上在機體旁畫出要按的方向。
6. 不會失敗：自己不會被擊破、沒有時間限制（結業考核除外），可以隨時再看示範或跳過（暫停選單也有）。

## 課程

| 課  | 名稱           | 練習                                                                     |
| --- | -------------- | ------------------------------------------------------------------------ |
| 1   | 基本近戰       | 靠近（距離圈變綠）、第一刀、三段連段（時機條）、硬直（走動的假人）、驗收 |
| 2   | 方向派生       | 前、側、後、連段中途換方向、小測驗（照指定方向依序起手）                 |
| 3   | 浮空與空中連段 | 打上去、跳躍取消、空中出招、完整的空中連段                               |
| 4   | 機動連接       | 衝刺斬、QB 取消後接回、對失衡目標的突進、驗收（會閃的假人）              |
| 5   | 武器連接       | 近戰接射擊、射擊打出失衡 → 突進、左右手交替（選修）                      |
| 6   | 處決           | 打出失衡、處決（按住）、處決的回報、驗收（會反擊的假人）                 |
| 7   | 防禦反擊       | 彈刀、彈刀之後必定失衡 → 處決、完美 QB、完美 QB 之後的反打、盾擊、綜合   |
| 8   | 結業考核       | 60 秒的技巧考試（4／7／10 種＝★／★★／★★★）、對教官的實戰                 |

- 武器沒有的招式（打樁機沒有「側」）那一步說明後跳過；觸控的攻擊鍵會自動切換射擊與近戰，近戰接射擊與左右手交替在觸控時說明後跳過。

## 三種操作方式

| 動作                                   | 鍵盤滑鼠（預設）         | 手把         | 手機觸控                                   |
| -------------------------------------- | ------------------------ | ------------ | ------------------------------------------ |
| 移動、方向（上＝前、下＝後、左右＝側） | W A S D                  | 左搖桿       | 左下的搖桿，或在攻擊鍵上滑動               |
| 近戰／射擊                             | 滑鼠左鍵／右鍵           | RT／LT       | 同一顆攻擊鍵：近戰距離內＝斬擊、遠處＝射擊 |
| QB／跳躍／突擊推進                     | 左 Shift／空白鍵／按住 F | B／A／按住 Y | 點 QB 鍵／跳躍鍵／按住 QB 鍵 0.4 秒        |
| 處決                                   | 按住左鍵                 | 按住 RT      | 按住攻擊鍵（斬擊時）                       |

- 說明文字的 `[move]` `[melee]`… 依裝置換成按鍵（`tutKey`）；方向 `[f]` `[s]` `[b]`＝鍵盤的移動鍵（`tutDirKeys`：W、S、「A 或 D」）、手把「左搖桿往上」、觸控「搖桿往上」。
- 觸控多一句說明（練習的 `touch`）：衝刺斬要等攻擊鍵變成斬擊再按、射擊打出失衡後攻擊鍵自動變成斬擊、處決是斬擊時按住、盾擊時攻擊鍵會變成斬擊。
- 觸控的盾擊：脈衝盾剛擋下攻擊的 0.5 秒內，攻擊鍵一律是近戰（`applySmartAttack`），遠處開槍的敵人也能盾擊。

## 實作

- **狀態**：`this.tut`（state 照舊 'play'，主迴圈在 `rangeTick` 之後呼叫 `tutTick`；dt 乘 `tutSpeed()`）。練習的階段 intro → demo → try → ok；一課完成時 state 'tutdone'（`#tutDoneCard`，主迴圈只算繪）。存檔 `save.story.tut`＝`{ les: { L1: { w: [完成過的武器], stars } }, intro, prize }`。
- **判定事件**：`MechEntity.tutE(k, o)`（只有教學中的玩家機體）→ `Game.tutEv`：press／early（排入下一招太早）／mv（出招：段號、fresh、突進、完美 QB 後）／hit（打中：目標、空中、突進）／whiff／swap／link／resume／qbc／qbEarly／qb／jc／exec／execKill／parry／pqb／shieldHit／hurt，假人被打出失衡是 stag、被擊破是 kill。招式依武器的招式圖加上標籤（`meleeTags`：c0…、combo、cEnd、f／s／b 路線與 fEnd、air／airEnd、dash、exec、bash、fin、launch、dive），練習的目標寫成「事件＋標籤＋次數＋條件」。
- **虛擬輸入**：示範與冒煙測試的自動操作設 `this.tutVirt`（`input.js` 的 `act` 只讀它、`player.js` 的移動方向改用它的 `wish`），所以示範走的是和玩家完全相同的輸入流程。
- **假人**：一般的敵方機體（`spawnEnemy`）＋`e.tutD`，`updateAI` 開頭由 `tutAI` 接手；AP 歸零時 `tutSaveEnt`（玩家一律不倒、假人只有 `kill` 的練習會被擊破，1.5 秒後重生）。
- **畫面**：`#tutPanel`（課名、練習、說明、進度、提示、時機條 `#tutBar`、示範／跳過按鈕）、HUD 畫布上的方向箭頭（`tutHud`）、假人腳下的距離圈（綠＝打得到、紅＝預警中）。
- **冒煙測試** `testMeleeTut`：`g.tutAuto`（try 也照腳本自動操作）＋`g.tutNoDemo`，每一課用不同的武器跑完，檢查每一步都在時限內過關、獎勵與存檔、選單的開放順序。`testMeleeTutDev:kb`／`:pad`／`:touch`：`g.tutAutoDev` 讓腳本寫進那個裝置真正的輸入（鍵盤的按鍵、手把的按鈕與 `padMove`、觸控的 `Touch_attack`／`Touch_qbHold`／`qbPulse`／`touchMove`，`tutDevApply`），所以按鍵對應、觸控攻擊鍵的切換、QB 鍵長按都照實際的流程跑；每個裝置 8 課、依裝置的說明文字、觸控跳過的練習。

## 時機與方向放寬（2026-10-27，試玩回饋）

- 近戰本身的輸入寬容見 `docs/melee-combo-design.md` 的「輸入的寬容」；教學中一律用寬鬆（`player.js` 的 `p.mAssist`）。
- 難度曲線：每個有 `speeds` 的練習都是 0.5 → 0.75 → 1 倍，每一段成功 2 次才加快（`tutSpeed`）；失敗 3 次放慢一級（原本 5 次）。連段中途派生（`mid`）也有慢速。
- 時機條（`queue`）＝這一招＋收招後的寬限，綠色從先行輸入的起點到寬限結束；按了顯示「記住了：接○○」，收招後顯示「收招了：快按，還接得上」。
- 失敗的原因多一種「太晚了」：上一招接得下去，卻在收招後才按、從第一招重來（`mv` 的 `late`）。說明文字改成「揮出去就可以按下一下（早按也會先記住）」「方向和攻擊鍵差不多同時按就好」。

## 起手派生不退開（2026-10-27）

- 近戰本身的改動見 `docs/melee-combo-design.md` 的「起手的方向派生」。第 2 課的說明改成「方向和攻擊鍵一起按（先按攻擊再馬上推方向也可以）」「近戰距離內推方向不會先退開」，觸控多一句「也可以在攻擊鍵上滑」。示範腳本把起手的預備當成出招中（`chain`／`wait idle` 等它出手）。
- 冒煙測試：`testMeleeTutDev:touch` 以真的 TouchEvent 在攻擊鍵上往下滑，檢查打出後派生、起手前沒有退開。

## 方向派生看按鍵（2026-10-27）

- 近戰改成看按鍵本身的方向（`docs/melee-combo-design.md` 的「方向派生看按鍵」），拿掉起手的預備與移動延遲。第 2 課的說明改成「按住 [f] 再按 [melee]」「方向就是你按的方向：上＝前、下＝後、左右＝側」；HUD 的箭頭畫成按鍵的方向（上／下／左右），提示的方向名稱是上／下／左右。示範腳本的 `press`／`chain` 用 `tutKeyVec`（按鍵 → 世界方向），QB 與跳躍的移動照舊相對假人（`tutDirVec`）；彈刀的時機條與示範回到原本的時機。觸控時中立起手不算「方向不對」（滑完才改成派生）。

## 彈刀與完美 QB 放寬（2026-10-27）

- 判定見 `docs/melee-combo-design.md` 的「反擊的提示與放寬」：假人的預警 0.9 秒前段只亮紅光，出手前 `CUE_LEAD`（0.3 秒）才出「!」與警報（`tutCue`），「!」出現之後到刀揮下來之間按 [melee]＝彈刀、按 [qb]＝完美迴避。`tutTele` 呼叫 `atkCue(…, { quiet: true })` 記下提示；時機條從「!」開始是綠色，失敗的說明是「「!」出現之前就按了」「「!」一出現就按」，第 7 課的說明與提示照改。

## 完成紀錄（2026-10-27）

- **8 課 × 5 把武器全部自動跑過**（`TUT_ALL=1`，每個練習都在時限內過關）。修正的地方：
  - 第 4 課「突進追擊」、第 5 課「射擊打出失衡 → 突進」：假人的開始距離改成依武器第一招的突進算（`dummy.lunge`＝突進距離的倍數，`tutDummyDist`，最遠 `LUNGE_MAX` 28 m 舊尺度）。原本固定 30／22 m：破碎爪與空手怎麼拉長突進都搆不到，打樁機的突進本來就夠遠、不算突進追擊。第 5 課的假人（等級 1）離太遠時走回到這個距離，不再固定 22 m。
  - 第 6 課「打出失衡」：ACS 累積的失衡（不是連段那條路徑）也送 `stag` 事件（`MechEntity.takeDamage`）。
  - 第 7 課「彈刀之後」：示範腳本的 `press` 在沒有出招、武器還在冷卻時等冷卻結束再按（原本彈刀後收招的冷卻吃掉了那一下，過了彈刀的 1 秒）。
  - 成功後放回開始位置（`tutResetLater`）改用遊戲時間（`T.resetIn`），放慢與固定 dt 的推進都一致。
  - 離開訓練（`tutExit`）一律把 state 換成 'sim'（清掉玩家的機體後停在 'play' 會讓主迴圈讀到空的 player）。
- **冒煙測試** `testMeleeTut`：作戰室的紅點與照順序開放、每一課換一把武器跑完、COAM（第 1 課 2,000、第 1～7 課合計 28,000）、結業挑一把近戰武器、存檔讀回、三種畫面大小的面板。考核的時限放寬（打中時的頓格讓遊戲時間比推進的時間慢）。除錯：`TUT_ONLY=L6:w_blade` 只跑一課，印出判定事件與示範腳本每一步的紀錄。
- **面板的版面**：改到左欄（任務資訊的下方，寬 `clamp(300px, 30vw, 420px)`）。原本在畫面上方中央，正好蓋住假人（假人在機體正前方＝畫面上方）；手機橫式在左上狀態欄之下、左下搖桿之上（寬 300 px、字小一級），不蓋住假人、機體與右邊的觸控按鈕。測試量面板和兩台機體在畫面上的位置與觸控按鈕的重疊。
