# 作戰室的操作介面

作戰室（主線的據點，`state` 'hub'，`game/hub.js`）的改版：原本是一張平面的 SVG 總覽圖＋右側 9 個文字按鈕，點委託跳到全黑的簡報畫面。改成一個 3D 的指揮室場景，正中央是立體的全像戰略桌。主線的資料（`SORTIES`、`BRIEFINGS`、`REGIONS`、開放條件）與流程不變。

提案頁的四個方向：A 全像戰略桌（XCOM 2、Ace Combat 7）、B 基地場景（XCOM 2 復仇者號、Hades）、C 委託清單＋情報面板（AC6）、D 指揮終端的分頁（MGS V iDroid）。

## 定案（使用者的選擇，2026-10-27）

1. **B＋A**：作戰室是一個基地場景（指揮室），場景的中心是 A 的全像戰略桌；其他設施（機甲庫的閘門、駕駛員區、模擬艙、通訊台、檔案櫃…）在場景裡，游標停留發光、點一下進入。
2. **簡報維持獨立的畫面**（改成有第一段的地形全像、路線圖示、委託方徽章）。
3. **設施選單用 A 的下方圖示列**（不用 D 的分頁）；場景裡的設施和圖示列是同一組入口。
4. **戰略桌是立體地形，而且跟關卡有關**：
   - 每個區域的地形是用**真的關卡生成**（`World`，同一個主題、變體、種子）取樣出來的高度圖與大型障礙物，所以峽谷、水壩、高台、平台長得和實際的地圖一樣。
   - 可以接的委託**預先排好出擊**（種子、排程、第一段的類型，存在存檔 `story.pre[sid]`），戰略桌上那一區顯示的就是第一段真的地圖，接下委託後照這份排程出擊（`campBegin` 用它）。

## 第四期：玻璃指揮塔與簡報的敵情（使用者的回饋，2026-10-27）

- 回饋：作戰室太暗、四周的牆與天花板讓轉視角時被擋住 → 從三個方案（開放式指揮甲板／保留房間＋遮擋淡出／玻璃指揮塔）選了 **C 玻璃指揮塔**。
  - 三面牆改成腰牆＋大片玻璃＋窗框，天花板改成鏤空的桁架（聚光燈、環形燈），鏡頭在哪個角度都不會被擋住；燈光調亮。
  - 指揮塔架在格納庫前段的半空（地板比格納庫高 `HUB_LIFT` 8 m，整備架在後方 `HUB_BAY` 22 m）：窗外是機甲庫的基地格納庫（`buildHangar('base')` 乘 `MS` 換成公尺，外部素材載入後重建成細緻的版本），整備架上是玩家目前的機甲，背景的整備位停著另外兩台。**模型來源**：玩家的機甲和機甲庫相同（`garageSource`：自己的模型組，沒有時伺服器預設組，再沒有時內建預設機甲），背景的兩台照電腦 AC（伺服器預設組優先）；進作戰室時 `lmRefresh` 讀一次，伺服器預設組晚一點讀好或換了模型組時（每 0.5 秒比對來源，`hubMechSync`／`hubBgSync`）自動換上。
  - **比例**：格納庫與機甲都照遊戲的尺度（機體約 9.7 m、技師約 1.8 m，`testHubUi` 量測），指揮塔裡的設施是人的尺寸。
  - 窗外隨機多放 9 個走動的技師與 4 台繞著通道跑的維修車（`render/hangar.js` 的 `addHangarLife`，避開整備架與指揮塔的支柱），格納庫原本的技師、吊車照舊動。機甲庫閘門移到後牆右側，正後方留給整備架上的機體。
- 簡報的敵情（`hub.js` 的 `briefIntelHtml`，`#brIntel`）：這次出擊會遇到的——
  - 終點 Boss：名稱、屬性的強弱（`res`）、打法（`intro`）。
  - 宿敵 AC（精英區段：區段的 `ace` 依存檔的抉擇，否則主題的 `THEME_ACE`）：組裝的三種防禦裡最弱的屬性、武器的攻擊屬性、打法；RUST 寫「每次組裝不同」。
  - 主題專屬敵人（`themeFoes`，依預排的每一段的主題與深度）：出現的主題與第幾段起、強弱與雷射倍率、打法。
  - 還沒遇過的也全部顯示（使用者的選擇）。

## 第五期：點場景模型進入設施、精細的設施模型（使用者的回饋，2026-10-28）

- 回饋：設施只能點文字標籤；要能點場景裡的模型，游標停在模型上時邊緣有發亮的線條；作戰室的模型太簡陋。
- **點模型**：每個設施是一個群組（`spots[id].obj`，`userData.hubSpot`），`hubPick` 從游標打射線（戰略桌擋在前面時不算、半透明的不算），游標停留＝`hubSpotHoverM`（手形游標），按下與放開在同一個設施且沒有拖曳（8 px 內）＝`hubSpotGo`＝按對應的圖示列按鈕；只有圖示列上看得到的設施（`hubSpotAvail`）能點。觸控沒有停留，點一下照樣進入。
- **發光輪廓**：每個設施的網格另外開一個圖層（`spots[id].layer`），游標停在模型或標籤上時 `hubOutline` 只畫那個圖層成白色遮罩（`overrideMaterial`、不更新陰影），再用全畫面的邊緣偵測加色疊在主畫面之後：外緣 2 px 的亮線＋往外的淡光暈＋很淡的內部填色，淡入淡出、微微脈動（顏色 `0x8fe0ff`）。被別的東西擋住的部分也畫輪廓。
- **精細的模型**（全部是程式模型，人的尺寸）：
  - 機甲庫閘門：上緣切角的厚門框（擠出）、兩片補強門板（補強板、橫肋、直補強、中縫警示條、模板字「HANGAR BAY 02」）、兩側液壓缸、燈箱看板「HANGAR ▸ 機甲庫」、旋轉警示燈、控制面板、警示條的門檻與軌道。
  - 駕駛員區：4 個置物櫃（通風孔、把手、發光名牌、編號），其中一個開著（駕駛服、頭盔）、長椅、頭盔與背包、上方的狀態螢幕。
  - 模擬艙：八角底座與燈環、萬向架與 3 支液壓缸、蛋形的艙（前方開口）、往上掀開的艙罩與玻璃、艙內的座椅與操縱桿與螢幕、電纜、旁邊的操作台。
  - 通訊台：三段的弧形控制台（鍵盤面板）、5 面螢幕與螢幕架、指揮椅、耳機與杯子、指示燈機櫃。
  - 檔案櫃：作戰紀錄的兩櫃（抽屜、把手、標籤燈、指示燈列、電纜架）、章節回顧的展示櫃（玻璃門、架上的資料核心、上面旋轉的全像書）。
  - 委託方看板：立架上的顯示牆、標題列、4 片委託方的徽章板、投射燈。
  - ECHO 的終端：八角基座、有溝槽的柱子與鰭片、投影機、光錐、浮著的全像與兩個轉動的環、電纜。
  - 戰略桌：踏板、裙邊的 48 根直肋、斜面環、桌緣下方的 5 個操作面板、腳下的燈帶。
  - 房間：金屬板地板（防滑紋）、腰牆的扶手與踢腳、窗框的粗細、天花板的斜撐與電纜架、聚光燈的燈罩、窗邊的兩個低矮控制台；格納庫的外部素材載入後（`hubRoomRich`）加監視器、工具箱、箱子、醫療箱、配電箱。
  - 貼圖都是畫布產生（面板、地板、警示條、螢幕、看板）；圓角方塊用 three.js 範例的 `RoundedBoxGeometry`（`lib/`）。建好後每個設施的靜態網格依材質合併（`mergeStatic`，會動的節點標 `userData.keep`）。
- 冒煙測試 `testHubUi`：游標停在通訊台的模型上＝發光輪廓、設施發光、手形游標，停在地板上沒有，點模型開啟通訊紀錄。

## 第六期：存檔終端（使用者的選擇，2026-10-31）

- 回饋：作戰室裡要有可以存檔、讀檔的地方。遊戲一直自動存在目前的存檔槽（`writeSave`），所以存檔終端**管理三個槽位**，不另做一套手動存檔。
- **位置與模型**（`render/hub-room.js`）：後牆中央偏左（`x = -1.4`），和右邊的 ECHO 的終端左右對稱（原本提案的後牆左側角落被駕駛員區的螢幕擋住，看不到）。資料核心的機櫃：正面三個插槽＝三個存檔（插著的資料匣、編號、狀態燈）、下方的螢幕與鍵盤、上方的看板「DATA CORE ／ 存檔」、兩側的燈條、側面的散熱鰭片、往後接地的電纜。
  - 插槽的燈（`R.saveSlots`，`hub-holo.js` 每格依 `hubSlotInfo` 上色）：使用中＝青色脈動、有資料＝白、空＝暗。
  - 自動存檔時兩側的燈條閃白一下（`writeSave` 記 `saveFlashT`）。
- **入口**：點模型或標籤（游標停留的發光輪廓）、下方圖示列的「存檔」（`btnHubSave`）。
- **面板**（`#hubSaveBox`，`game/save.js` 的 `hubSaves`／`hubSaveRender`／`hubSaveAct`）：三張槽位卡（主線的周目與章節、進行中的出擊與區段、COAM、駕駛員等級、最後遊玩）。
  - 使用中的存檔：只有「匯出」（一直在自動存）。
  - 其他存檔：「存到這一格」（把目前的進度含紀錄點複製過去；有資料時先確認）、「讀取」（確認後 `useSlot` 換過去，作戰室依那份存檔重建）、「匯出」、「匯入」（覆蓋時確認）、「刪除」（確認）。
  - 空的存檔：「存到這一格」、「匯入」。
  - 確認一律用 `uiConfirm`（手把可以操作）。
- **抉擇前備份**：接下有陣營抉擇的委託（區段有 `choice`：c2s2、c4s2、c6s3）時，`briefGo` 先存一份（localStorage `rubicon_save_bk_<槽位>`，每個存檔最近一份，不佔槽位）；面板的「抉擇前備份」卡片可以讀回（確認後取代使用中存檔的進度）。那個槽位被覆蓋、匯入或刪除時，備份一起刪掉。
- 多人時沒有作戰室，所以不受影響；不改網路協定。
- 冒煙測試 `testHubSave`：點模型開啟、插槽燈、存到空的槽位（進行中的出擊跟著複製）、覆蓋的確認（取消／確定）、讀取另一個槽位（作戰室依它重建、原本的已自動存好）、刪除、使用中的只能匯出、抉擇前備份（沒有抉擇的委託不存、讀回）、手機橫式。

## 場景（`render/hub-room.js`）

- 公尺為單位（人的尺寸，不是機甲的尺度）。房間約 22×16 m：金屬地板、牆面的面板與燈條、天花板的燈；正中央是圓形的全像戰略桌（直徑約 6 m，桌面發青光）。
- 設施（`ROOM_SPOTS`，每個有錨點位置與入口）：
  - 戰略桌（`table`）：總覽圖本身，不開新畫面。
  - 機甲庫閘門（`garage`）：後方牆面的大閘門，看得到格納庫的燈光。
  - 駕駛員區（`pilot`）：置物櫃與座椅。
  - 模擬艙（`sim`）：膠囊狀的艙。
  - 通訊台（`log`）：通訊紀錄。
  - 委託方看板（`fac`）：四家委託方的徽章牆。
  - 檔案櫃（`record`）：作戰紀錄（另有章節回顧 `story`）。
  - ECHO 的終端（`echo`）：第 3 周目或回收過記憶片段時才亮。
  - 存檔終端（`save`）：三個存檔的管理（第六期）。
- 每格 `tickHubRoom`：燈條呼吸、全像掃描線、設施的發光（游標停留／有新東西時亮）。

## 全像戰略桌（`render/holo-map.js`）

- 大陸的底板（依 `REGIONS` 的位置，100×100 的總覽座標對到桌面）＋每個區域一塊地形（區域圈的大小）：高度圖做成網格，材質是加色的青色全像（高度著色、等高線、掃描線，`ShaderMaterial`），大型障礙物（`world.obstacles` 的方塊與圓柱，過濾掉小物件）是細線框；水面是半透明的平面。
- 區域的地形來源（`game/hub-holo.js` 的 `hubHoloTile`）：
  - 有可以接的委託在這一區時：那個委託預排的第一段（主題、變體、地標、種子）。
  - 否則：這個區域主題的代表地圖（固定種子，`REGION_THEME`）。
  - 還沒開放的區域：只畫輪廓與「第 n 章開放」，不畫地形。
- 取樣：在不加入畫面的場景裡建 `World`（與 `campEnterSeg` 相同的參數），讀 `world.h`（降到 64×64）與障礙物，然後 `dispose`；結果依「主題|變體|地標|種子」快取在記憶體。每格最多建一個（約 0.1～0.5 秒），還沒好的區域先畫平的。
- 委託的標記：桌上立一根光柱（委託方的顏色；完成＝綠、鎖住＝灰、周目限定＝紫、ECHO＝金），頂端的標籤是 DOM 按鈕（`#hubMap .hubNode[data-sid]`，位置每格由 3D 投影；有抉擇的帶 ⚑），可以點、手把可以選。鎖住的委託點了在上方顯示開放條件（`#hubCap`）。
- 鏡頭：預設從桌子斜上方看整張總覽圖（房間在周圍）；游標停在委託上時鏡頭稍微推向那一區。拖曳可以繞桌子轉一點。

## 畫面上的介面（DOM，疊在 3D 上）

- 上方列：作戰室、章節（`#hubChapter`）、COAM（`#hubCoam`）、`#hubCap`。
- 進行中的出擊（`#hubActive`）：橫幅（委託名、區段進度格、「繼續出擊」`#btnHubResume`、小的「放棄」`#btnHubDrop`）。
- 持有的模組（`#hubMods`）：委託方顏色的晶片。
- 下方圖示列（`#hubDock`）：機甲庫、駕駛員、委託方、通訊、ECHO、章節回顧、模擬器、作戰紀錄、存檔、回標題（按鈕 id 照舊 `btnHub*`）；有新東西的標紅點。場景裡設施的名稱標籤（`.hubSpot`）也是同一組入口。

## 簡報（獨立畫面，第二期）

- 背景是這個委託第一段的地形全像（同一份預排），慢慢旋轉。
- 委託方徽章、台詞逐字（照舊）、作戰目標；路線改成區段圖示列（戰鬥、破壞、防衛、護送、突破、補給、情報、精英、Boss，隨機的是「?」，換主題時換底色）；報酬與按鈕。
