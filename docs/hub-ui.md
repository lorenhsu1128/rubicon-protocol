# 作戰室的操作介面

作戰室（主線的據點，`state` 'hub'，`game/hub.js`）的改版：原本是一張平面的 SVG 總覽圖＋右側 9 個文字按鈕，點委託跳到全黑的簡報畫面。改成一個 3D 的指揮室場景，正中央是立體的全像戰略桌。主線的資料（`SORTIES`、`BRIEFINGS`、`REGIONS`、開放條件）與流程不變。

提案頁的四個方向：A 全像戰略桌（XCOM 2、Ace Combat 7）、B 基地場景（XCOM 2 復仇者號、Hades）、C 委託清單＋情報面板（AC6）、D 指揮終端的分頁（MGS V iDroid）。

## 定案（使用者的選擇，2026-10-27）

1. **B＋A**：作戰室是一個基地場景（指揮室），場景的中心是 A 的全像戰略桌；其他設施（機甲庫的閘門、駕駛員區、模擬艙、通訊台、檔案櫃…）在場景裡，游標停留發光、點一下進入。
2. **簡報維持獨立的畫面**（改成有第一段的地形全像、路線圖示、委託方徽章）。
3. **設施選單用 A 的下方圖示列**（不用 D 的分頁）；場景裡的設施和圖示列是同一組入口。
4. **戰略桌是立體地形，而且跟關卡有關**：
   - 每個區域的地形是用**真的關卡生成**（`World`，同一個主題、變體、種子）取樣出來的高度圖與大型障礙物，所以峽谷、水壩、高台、平台長得和實際的地圖一樣。
   - 可以接的委託**預先排好出擊**（種子、排程、第一段的類型，存在存檔 `story.pre[sid]`），戰略桌上那一區顯示的就是第一段真的地圖，接下委託後照這份排程出擊（`campBegin` 用它）。

## 場景（`render/hub-room.js`）

- 公尺為單位（人的尺寸，不是機甲的尺度）。房間約 22×16 m：金屬地板、牆面的面板與燈條、天花板的燈；正中央是圓形的全像戰略桌（直徑約 6 m，桌面發青光）。
- 設施（`ROOM_SPOTS`，每個有錨點位置與入口）：
  - 戰略桌（`table`）：總覽圖本身，不開新畫面。
  - 機甲庫閘門（`garage`）：後方牆面的大閘門，看得到格納庫的燈光。
  - 駕駛員區（`pilot`）：置物櫃與座椅。
  - 模擬艙（`sim`）：膠囊狀的艙。
  - 通訊台（`log`）：通訊紀錄。
  - 委託方看板（`fac`）：四家委託方的徽章牆。
  - 檔案櫃（`record`）：作戰紀錄（另有章節回顧 `story`）。
  - ECHO 的終端（`echo`）：第 3 周目或回收過記憶片段時才亮。
- 每格 `tickHubRoom`：燈條呼吸、全像掃描線、設施的發光（游標停留／有新東西時亮）。

## 全像戰略桌（`render/holo-map.js`）

- 大陸的底板（依 `REGIONS` 的位置，100×100 的總覽座標對到桌面）＋每個區域一塊地形（區域圈的大小）：高度圖做成網格，材質是加色的青色全像（高度著色、等高線、掃描線，`ShaderMaterial`），大型障礙物（`world.obstacles` 的方塊與圓柱，過濾掉小物件）是細線框；水面是半透明的平面。
- 區域的地形來源（`game/hub-holo.js` 的 `hubHoloTile`）：
  - 有可以接的委託在這一區時：那個委託預排的第一段（主題、變體、地標、種子）。
  - 否則：這個區域主題的代表地圖（固定種子，`REGION_THEME`）。
  - 還沒開放的區域：只畫輪廓與「第 n 章開放」，不畫地形。
- 取樣：在不加入畫面的場景裡建 `World`（與 `campEnterSeg` 相同的參數），讀 `world.h`（降到 64×64）與障礙物，然後 `dispose`；結果依「主題|變體|地標|種子」快取在記憶體。每格最多建一個（約 0.1～0.5 秒），還沒好的區域先畫平的。
- 委託的標記：桌上立一根光柱（委託方的顏色；完成＝綠、鎖住＝灰、周目限定＝紫、ECHO＝金），頂端的標籤是 DOM 按鈕（`#hubMap .hubNode[data-sid]`，位置每格由 3D 投影；有抉擇的帶 ⚑），可以點、手把可以選。鎖住的委託點了在上方顯示開放條件（`#hubCap`）。
- 鏡頭：預設從桌子斜上方看整張總覽圖（房間在周圍）；游標停在委託上時鏡頭稍微推向那一區。拖曳可以繞桌子轉一點。

## 畫面上的介面（DOM，疊在 3D 上）

- 上方列：作戰室、章節（`#hubChapter`）、COAM（`#hubCoam`）、`#hubCap`。
- 進行中的出擊（`#hubActive`）：橫幅（委託名、區段進度格、「繼續出擊」`#btnHubResume`、小的「放棄」`#btnHubDrop`）。
- 持有的模組（`#hubMods`）：委託方顏色的晶片。
- 下方圖示列（`#hubDock`）：機甲庫、駕駛員、委託方、通訊、ECHO、章節回顧、模擬器、作戰紀錄、回標題（按鈕 id 照舊 `btnHub*`）；有新東西的標紅點。場景裡設施的名稱標籤（`.hubSpot`）也是同一組入口。

## 簡報（獨立畫面，第二期）

- 背景是這個委託第一段的地形全像（同一份預排），慢慢旋轉。
- 委託方徽章、台詞逐字（照舊）、作戰目標；路線改成區段圖示列（戰鬥、破壞、防衛、護送、突破、補給、情報、精英、Boss，隨機的是「?」，換主題時換底色）；報酬與按鈕。

## 分期

### 第一期：指揮室場景與全像戰略桌（已完成）

- `render/hub-room.js`、`render/holo-map.js`、`game/hub-holo.js`（地形取樣與快取、鏡頭、標記投影、設施熱點）。
- `hub.js` 的 `renderHub` 改成更新 DOM 疊層與戰略桌；主迴圈在 `state` 'hub' 時算繪作戰室場景（`hubScene`／`hubCam`，有渲染風格時用自己的 `StylePipeline`）。
- 預排出擊：`hubPrePlan(sid)`（campaign.js）、`campBegin` 使用；`campSegWorld` 是 `campEnterSeg` 與戰略桌共用的 World 參數，所以兩邊的地形相同（`testHubUi` 量過誤差 0）。
- 鏡頭在游標停留時不動（標籤要能點，冒煙測試的點擊要等元素穩定）；拖曳背景繞桌子轉，停手後回到正面。
- 冒煙測試 `testHubUi`（第三期再補手把與更多版面）。

### 第二期：簡報（已完成）

- 背景：作戰室場景照舊算繪，桌上只留這個委託第一段的地形（`hubBriefShow`，放大到整張桌子、慢慢轉，同一份預排與快取），鏡頭靠近、畫面中心移到右側（`setViewOffset`），右下角標出第一段的主題・變體與類型（`#brMapCap`）。
- 路線：每個區段一個圖示（`.brSeg`，第一段是預排好的類型、固定類型照寫、會抽的是「?」），換主題時換底色，Boss 紅框，滑鼠停留看主題、變體與類型。委託方徽章沿用 `speakerBadge`。

### 第三期：平板、手機、手把、冒煙測試（已完成）

- 平板橫式（1180×820）同一個版面；設施的標籤在場景裡的位置超出畫面時停在畫面邊緣（`hubLabels` 的 edge）。
- 手機橫式（`max-height: 540px`）：圖示列只剩圖示、設施與區域名稱的標籤隱藏、鎖住的委託只留圖示；簡報改成滿版的深色底、不顯示第一段的說明框。
- 手把：委託的標籤（有 onclick 的 div）、設施標籤與圖示列都是可操作的元素，十字鍵依畫面位置移動（`testPadUi` 檢查作戰室有可操作的元素）。
- 冒煙測試 `testHubUi`：預排的出擊、區域地形取自關卡生成且以種子決定、委託標籤與新通訊的紅點、設施標籤開啟通訊紀錄、簡報的第一段地形與路線圖示、出擊照預排且第一段的地形和戰略桌相同、手機橫式。
