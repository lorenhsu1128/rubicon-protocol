# RUBICON PROTOCOL — GLB 模型製作規格

遊戲中的每個 3D 模型都有一個「模型槽」。沒有 GLB 的槽位會顯示程式產生的模型（three.js），提供 GLB 後就改用 GLB。
所有規格都可以在**模型庫**（`dist/model-library.html`，伺服器上的 `/models`）逐項檢查。

## 1. 工作流程

1. 打開模型庫，找到要製作的槽位，記下格子下方的**槽位 id**（例如 `head/h_std`）。
2. 在檢視窗按「**下載範本 GLB**」：這是把現有程式模型照本規格匯出的檔案，匯入 Blender 等軟體即可當作比例、原點、朝向、節點命名與材質命名的參考。
3. 製作完成後匯出 GLB，**拖到模型庫對應的格子上**（或在檢視窗按「載入 GLB…」）。檔案只存在你的瀏覽器裡，不會影響遊戲。
4. 看檢視窗右側的**規格檢查**（✓ 通過、⚠ 警告、✗ 錯誤），並用「並排對照」「疊合對照」「組合預覽」「動作預覽」確認外觀。
5. 確定採用後，把檔案放到 `src/assets/models/<槽位 id>.glb`（模型庫的「下載（依槽位命名）」會給出正確檔名），執行 `npm run build`，GLB 就會內嵌進遊戲與模型庫。
6. 模型庫上方的「匯出對照表」可以輸出所有槽位的來源、檔案、目標路徑、尺寸與檢查結果（JSON）。

## 2. 單位、座標與朝向

| 項目 | 規格 |
|---|---|
| 單位 | 1 單位 = 1 公尺（模型庫所有尺寸都以公尺標示） |
| 上方 | +Y |
| 正面 | **+Z**（glTF／Blender 預設匯出方向即可；遊戲載入時會自動轉成遊戲內的 −Z） |
| 參考尺寸 | 玩家機甲高約 4.2 m（含天線），人形剪影 1.8 m |
| 格式 | glTF 2.0 二進位（.glb），貼圖內嵌 |

## 3. 原點（接合點）

| 分類 | 槽位 id 前綴 | 原點位置 | 製作尺寸 |
|---|---|---|---|
| 頭部 | `head/` | 頸部接合處（頭部底面中心） | ×1 |
| 核心 | `core/` | 腰部接合處（軀幹底面中心） | ×1 |
| 手臂 | `arms/` | **肩部樞紐**；只做右臂，左臂由遊戲鏡像 | ×1 |
| 腳部 | `legs/` | 地面中心（腳底所在平面） | ×1 |
| 推進器（背包） | `booster/` | 背包中心 | ×1 |
| 手持武器 | `weapon/` | **握把**；槍口朝正面 | **遊戲內實際尺寸**（見模型庫「遊戲尺寸」） |
| 背部武器 | `back/` | 肩上掛點 | **遊戲內實際尺寸** |
| 完整機甲 | `mech/` | 地面中心（兩腳之間） | ×1（遊戲依倍率放大，例如 Boss ×2.6） |
| 非機甲／載具 | `vehicle/` | 地面中心 | ×1（同上） |
| 地圖物件、小物件 | `prop/`、`small/` | 地面中心（彈體為彈體中心） | ×1 |

原點位置一律以「下載範本 GLB」的原點為準。模型庫會比對 GLB 與程式模型的外框：尺寸差超過 15% 警告、超過 50% 錯誤；外框中心或底部高度明顯不同時，代表原點可能放錯。

## 4. 節點命名（會動的部位）

遊戲的機甲動作是由程式直接轉動「關節節點」，**不使用蒙皮骨架**（skinned mesh 會被判為錯誤）。
每個關節是一個節點，網格掛在該節點底下；節點的**原點放在關節轉軸**，四肢沿 −Y 方向下垂。
腿部關節的靜止旋轉會被當作動作的基準角度（可以保留膝蓋微彎）；手臂與頭部的角度由遊戲直接設定，靜止時旋轉請保持為 0（範本中手臂彎曲的角度是程式的展示姿勢，可忽略）。

### 完整機甲（`mech/`）

```
（根）
├─ legs                       腿部根節點
│   ├─ leg_l_thigh → leg_l_knee → leg_l_foot     左腿：大腿 → 小腿 → 腳
│   └─ leg_r_thigh → leg_r_knee → leg_r_foot     右腿
└─ torso                      軀幹（腰部轉軸）
    ├─ head                   頭（頸部轉軸）
    ├─ arm_r_shoulder → arm_r_upper → arm_r_fore → arm_r_hand → mount_weapon_r
    ├─ arm_l_shoulder → arm_l_upper → arm_l_fore → arm_l_hand → mount_weapon_l
    ├─ mount_back_r、mount_back_l      肩上武器掛點（選用）
    └─ nozzle_l、nozzle_r              推進器噴口（選用，遊戲會縮放它當作噴焰）
```

- 必要節點：`legs`、`torso`、`head` 與兩側手臂四節。缺少時只能靜態顯示（模型庫會列出缺少的節點）。
- 四足機甲的腿改用 `leg_fl`、`leg_fr`、`leg_bl`、`leg_br`（前左、前右、後左、後右），各自再分 `_thigh／_knee／_foot`。
- 履帶型可以沒有腿部節點（`legs` 底下只有網格）。腿型也可以在 `legs` 節點的自訂屬性（extras）寫 `legType`：`biped`／`reverse`／`quad`／`tank`。

### 手臂部件（`arms/`，選用）

`arm_upper` → `arm_fore` → `arm_hand` → `mount_weapon`。有這些節點時，組合預覽與遊戲中的手臂才會彎曲。

### 腳部部件（`legs/`，選用）

`leg_l_thigh／knee／foot`、`leg_r_thigh／knee／foot`。沒有時腳不會擺動。

## 5. 材質與配色

- 一律使用 **PBR 材質**（Principled BSDF → glTF metallic-roughness）。受擊閃光會改變材質的自發光，無光照（unlit）材質只適合貼花或發光面。
- **依材質名稱換色**：名稱為下列其中之一的材質（不分大小寫，可帶 `.001` 這類後綴），遊戲會依陣營配色（玩家、敵人、具名 AC、多人四色）改成對應顏色，貼圖只負責髒污、面板線等明暗細節：

  | 名稱 | 用途 |
  |---|---|
  | `main`、`main2`、`main3` | 主色（大面積裝甲） |
  | `sub` | 副色 |
  | `acc` | 點綴色（黃色條紋等） |
  | `joint` | 關節、機械部分 |
  | `grey` | 灰色裝甲 |
  | `gun` | 武器金屬 |
  | `visor`、`glow` | 面罩、發光部位（會一併設定自發光） |

- 其他名稱的材質保留原本的顏色與貼圖（不隨陣營改變）。兩種方式可以混用。
- 墨線描邊由遊戲自動產生，模型不需要自己做描邊。

## 6. 預算

| 類別 | 三角面 | 繪製次數* | 貼圖最大邊長 | 檔案大小 |
|---|---|---|---|---|
| 機甲部件（頭、核心、手臂、腳、推進器） | 3,000 | 80 | 1024 px | 2 MB |
| 武器 | 2,000 | 30 | 1024 px | 1.5 MB |
| 完整機甲 | 25,000 | 200 | 1024 px | 4 MB |
| Boss 機甲 | 40,000 | 240 | 2048 px | 8 MB |
| 載具 | 8,000 | 100 | 1024 px | 3 MB |
| Boss 載具 | 40,000 | 160 | 2048 px | 8 MB |
| 地圖物件 | 2,000 | 30 | 1024 px | 1.5 MB |
| 小物件（掉落物、彈體） | 500 | 8 | 512 px | 0.5 MB |

\* 繪製次數包含遊戲自動補上的描邊（約為網格數 ×2）；同一材質的網格請盡量合併。三角面超過預算 1.5 倍判為錯誤，其他超過預算為警告。

## 7. 其他注意事項

- GLB 內的動畫不會被使用（動作由程式驅動），模型庫只會提示。
- 不要在根節點加整體縮放或位移來「修正」尺寸，請直接在建模軟體裡以正確單位製作。
- 地圖物件在遊戲中的尺寸有隨機範圍（模型庫備註欄有寫）；之後換成 GLB 時以代表尺寸製作，遊戲再依需要縮放。
- 規格檢查的數值定義在 `src/render/glb.js`（`GLB_BUDGET`、`MECH_NODES`、`PALETTE_SLOTS`），調整時請同步更新本文件。
