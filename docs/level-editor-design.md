# 關卡編輯器 設計文件

> 狀態：設計討論中（第 11 節的待決事項定案後開始實作）。
> 參考 Halo 的 Forge（在遊戲世界裡飛行擺放、隨時試玩）、星海爭霸／魔獸爭霸 3 的地圖編輯器（區域＋觸發器）、超級瑪利歐創作家（玩家創作與分享、通關驗證）。
> 名稱、數字都是暫定值，實作與試玩後再調。

## 1. 目標與範圍

| 項目 | 決定 |
|---|---|
| 使用者 | 玩家創作、互相分享（UI 要友善，存檔格式要長期相容） |
| 位置 | 遊戲裡的新畫面（`state` 'editor'），可以直接切換成試玩 |
| 內容 | 方案 2（Forge 式擺放）＋方案 3（地形筆刷、觸發器、自製出擊） |
| 敵人 | 擺放位置＋行為（守住、警戒、巡邏路線、進攻），觸發器可以改行為、派增援 |
| 分享與多人 | 第一期就有：區網伺服器上傳／瀏覽／下載，多人房間玩自訂關卡 |
| 裝置 | 電腦（滑鼠＋鍵盤）與平板（觸控）都能編輯；手機橫式只能玩、不能編輯（畫面太小，入口顯示提示） |

不做：自訂模型（模型交給模型庫的模型組）、自訂武器與零件數值、自寫程式碼（觸發器只能用內建的事件／條件／動作組合）。

## 2. 整體結構

```
自訂關卡（.rubicon-level，一個 JSON）
 ├ 底圖：主題、變體、種子（或空白）、時間、天候、作戰區域
 ├ 地形：高度圖（整張，絕對高度）＋水面高度
 ├ 物件：擺放的掩體、平台、坡道、可破壞物件、裝飾（＋移除的產生器物件）
 ├ 機能物件：出生點、補給箱、補給台、資料終端、出口、目標設施
 ├ 路徑：折線（巡邏、護送車隊、運輸機航線）
 ├ 區域：方形／圓形（觸發器用）
 ├ 單位：敵人、友軍，分成群組（group）
 └ 觸發器：事件 → 條件 → 動作；計數器
```

入口：標題的「自訂關卡」→ 關卡選單（`state` 'levels'）：
- 我的關卡（本機）：新建、編輯、試玩、複製、刪除、匯出、上傳。
- 伺服器上的關卡（只在伺服器網址時）：清單、搜尋、下載、直接遊玩。
- 匯入檔案。
- 出擊：選關卡 → 機甲庫整備（多人：大廳的房間模式「自訂關卡」）。

## 3. 底圖與地形

### 3.1 底圖

新建關卡時選：
- **從產生器開始**：主題、變體、種子（可以按「換一張」重抽）、是否保留產生器的物件（全部／只留大型結構／不留）。地標、地形特徵（橋、高架橋、掩體群、公路…）照種子生成。
- **空白**：主題＋平地或輕微起伏，沒有地形特徵與物件（最適合從零開始蓋）。

時間（白天／黃昏／夜間／黎明）、天候、作戰區域（全場／狹長／小型，或自己畫矩形）、場地大小（230 m 預設，可選 150／300）在「關卡設定」改。

### 3.2 地形以整張高度圖保存

遊戲之後的版本可能改產生器（地形特徵、變體），只存「種子」的話舊關卡會變形。所以：
- 地形一律存**整張絕對高度圖**（230 m／2.5 m＝93×93 點，Int16 以 2 cm 為單位，base64 約 23 KB），不靠種子重算。
- 產生器的大型結構（壩體、多層平台、橋、地標）照種子重建，關卡記錄產生它的 `gen` 版本；版本不同時讀取照常，但編輯器顯示「底圖結構可能和製作時不同」，作者重新存檔就更新版本。
- 「移除的產生器物件」以 `{ kind, x, z }` 記錄（以位置最接近、同種類比對），不靠生成順序的索引。

World 端：`opt.level`（關卡資料）存在時，`buildTerrain` 在算完高度後改用關卡的高度圖（平滑之後，所以存進去的就是最終值），之後的流程（地形特徵、物件）照常，但物件的散布改成依關卡設定；全部在原本的亂數呼叫之後套用，**不影響一般地圖與主線**。

### 3.3 地形筆刷

| 筆刷 | 效果 |
|---|---|
| 抬高／降低 | 依強度與半徑（平滑衰減） |
| 整平 | 拉到按下時那一點的高度（或輸入高度） |
| 平滑 | 和周圍平均 |
| 斜坡 | 拖一條線，兩端高度之間做平滑坡（給機甲上台地） |
| 雜訊 | 加起伏 |
| 水面 | 設整張地圖的水面高度（`theme.water.level`，涉水判定照現有的 `waterDepth`） |

- 坡度提示：超過機甲能走的坡度（`slopeOK`）的地方以紅色顯示。
- 筆刷每一筆是一個復原項目（存改動範圍的前後高度）。
- 筆刷改高度後，物件依「貼地」設定跟著地形升降（`snap: 'ground'`），或保持絕對高度。
- 虛空主題（洋上都市、高空軌道）：降到 `void.y` 以下就是虛空，照現有判定。

## 4. 物件

### 4.1 可擺放物件表（`data/placeables.js`）

現有的地圖物件網格都是純函式，但碰撞形狀寫在 world.js 的呼叫端，所以新增一張「可擺放物件表」，每一項：

```js
{ id: 'container', name: '貨櫃', cat: 'cover', themes: null /* 全部 */,
  build: (p, pal) => buildContainer(p.w, p.h, p.d, ...),   // 純函式網格
  shape: (p) => [{ box: [-w/2, w/2, -d/2, d/2], y: 0, top: h }],   // 碰撞（物件座標）
  params: { w: [2, 12, 6], h: [2, 6, 2.6] },  // 可調尺寸 [最小, 最大, 預設]
  hp: 900,          // 可破壞時的耐久（沒有＝不可破壞）
  stand: true,      // 可以站上去（box 頂面）
  slot: 'prop/container' }   // 模型槽（GLB 照樣換得上）
```

分類：
- 掩體與牆
- 平台、坡道、橋面（可站上去，用現有的 `addDeck`、`ramps`）
- 貨櫃與堆疊
- 可破壞物件（岩石、儲槽、卡車…）
- 主題物件（各主題的 `catalog`）
- 地標
- 裝飾（不碰撞）

先做通用的與各主題常用的約 40～60 種，之後再補。主題物件預設只列在該主題的調色盤，但可以勾「顯示所有主題」。

### 4.2 擺放規則

- 位置 x／y／z、朝向 yaw、尺寸參數；碰撞照現有的 box／circle：**有 box 碰撞的物件朝向只能 90° 一格**（現有碰撞是軸對齊的；`addBig` 的 `spot.q` 也是 90°），只有圓形碰撞與裝飾可以自由轉向。
- 吸附：格子（0.5／1／2.5 m）、對齊旁邊物件的邊、貼地／貼在下面物件的頂面（堆貨櫃）。
- 複製、多選、群組移動、陣列複製（一次放一排）。
- 物件上限 600（超過時提示；效能與快照大小的考量），單位上限 120。
- 生成順序：關卡的物件在產生器之後依陣列順序建立（不用亂數），所以多人各端一致。

### 4.3 機能物件

| 物件 | 用途 |
|---|---|
| 玩家出生點 | 1～4 個（多人依人數分配），朝向 |
| 補給箱 | 現有的據點補給箱（`CACHE_KINDS`），可以指定守衛群組 |
| 補給台 | 主線的補給台（站上去回復） |
| 資料終端 | 站滿 n 秒（觸發器事件「終端完成」） |
| 出口 | 觸發器開啟後出現，走進去＝完成（或觸發事件） |
| 目標設施 | 敵方（要破壞）或友方（要守住），耐久可調 |
| 敵人生成點 | 增援的出現位置（觸發器指定；邊緣進入或空降） |

## 5. 單位

### 5.1 擺放

- 種類：一般敵人（`ENEMY_TYPES`）、主題專屬敵人（`FOES`）、敵對 AC（`AC_ROSTER`、具名 AC、宿敵 `ACES`）、Boss（`BOSS_DEFS`，每關最多 1 隻，Boss 自己的部位照原本生成）、友軍（友軍 AC、護送車隊）。
- 不限「遇過的」：自訂關卡可以放所有敵人（待決事項 11.2）。
- 每個單位：位置、朝向、群組、行為、出現方式（開場就在／等觸發器）、強度（跟著關卡等級，或個別 ×0.5～×2）。
- 群組：命名（例如「A 隊」「倉庫守衛」），觸發器以群組為單位操作；顏色標示。

### 5.2 行為

| 行為 | 說明 |
|---|---|
| 進攻 | 現在的 AI（找玩家打） |
| 守住 | 站在原地（可以轉向、開火），不追 |
| 警戒 | 守在原地，玩家進入半徑或受傷時整群出動（現有據點守衛 `guardIdle` 的做法） |
| 巡邏 | 沿路徑走（循環／來回），速度可調；發現玩家（視線＋距離）或受傷時整群出動，可設定「出動後回到路徑」 |
| 撤退 | 往指定點移動，到了就離場（不算擊破，同運輸機的 `depart`） |

- 實作：`updateAI` 開頭和據點守衛同樣的方式攔截（`edAI`），移動用現有的 `move()`（所以碰撞、跳躍、客機預測都照舊）。
- 飛行單位的巡邏路徑可以設高度；四足、履帶照它的移動方式。
- 護送車隊：沿路徑（不一定是公路）前進，用主線的 `convoy` 行為改成讀路徑。

### 5.3 路徑與區域

- 路徑：點選地面加點，可以拖曳點、插入、刪除；顯示箭頭與方向；點可以設「停留 n 秒」。
- 區域：方形（可旋轉）或圓形，名稱＋顏色；試玩時隱藏（除非觸發器設定顯示，例如「抵達這裡」的目標圈）。

## 6. 觸發器

### 6.1 結構

```
觸發器「倉庫被發現」
  事件：玩家進入區域「倉庫」
  條件：計數器「警報」= 0
  動作：
    1. 文字演出 WARNING「增援接近」
    2. 通訊 ECHO「倉庫的守衛發現你了。」
    3. 生成群組「增援 B」（空降，在生成點「北門」，預告方向）
    4. 群組「倉庫守衛」改成「進攻」
    5. 計數器「警報」+1
  選項：只觸發一次／每次都觸發、一開始啟用
```

UI 是卡片清單（不是節點圖），平板也好點：每個觸發器一張卡，展開後是事件、條件、動作三段，每段用下拉選單加項目，參數用選單挑（區域、群組、路徑的下拉，或在場景中點選）。

### 6.2 事件

- 任務開始、經過 n 秒、每 n 秒
- 玩家（任一／全部）進入／離開區域
- 群組全滅、群組剩 n 台、單位 AP 低於 n%（Boss 換型態也算）
- 物件被破壞、目標設施被毀、補給箱打開、資料終端完成、玩家走進出口
- 計數器變化、其他觸發器執行完
- 玩家倒下、全員倒下

### 6.3 條件

計數器比較、群組存活數、玩家人數、已經過時間、其他觸發器是否觸發過；可以 AND／OR。

### 6.4 動作

| 類別 | 動作 |
|---|---|
| 單位 | 生成群組（開場位置／生成點邊緣進入／空降，可附 ECHO 的方向預告）、改群組行為、群組撤退、移除群組 |
| 任務 | 顯示／更新目標文字（HUD 左上）、開啟出口、任務成功、任務失敗、開始倒數（HUD 顯示，到 0 觸發事件） |
| 演出 | 文字演出（選 CUE：橫幅、中央訊息、WARNING…，自己打字）、通訊（說話者：ECHO、指揮官、自訂名字；台詞）、警報音、鏡頭震動 |
| 場景 | 顯示／隱藏區域圈、移除物件（開門）、顯示物件、改天候 |
| 獎勵 | 修理全員、補充彈藥、掉落補給（遵守待決事項 11.1 的獎勵規則） |
| 流程 | 計數器設定／加減、啟用／停用觸發器、延遲 n 秒後繼續 |

- 沒有寫勝利條件的關卡：預設「敵人全滅＝成功」（和自由出擊相同），全員倒下＝失敗。
- 觸發器只在房主／單機執行；動作都轉成現有的事件（`msg`、`comm`、`banner`、`wave`、`fx`）給客機，所以只要新增「目標文字」「倒數」「區域圈」的同步。

### 6.5 自製出擊（多段）

一個關卡檔可以有 1～5 張地圖（區段），動作「前往下一段」＝走進出口後轉場（借用主線的轉場畫面與 AP／彈藥的帶入 `carry`）。最後一段的勝利＝出擊完成。第一期只做單張地圖，多段放在第 3 期。

## 7. 編輯器畫面

### 7.1 版面（電腦）

```
┌─────────────────────────────────────────────────────┐
│ 檔案▼ 復原 重做  [選取][物件][地形][單位][路徑][區域][觸發器]  ▶試玩 │
├──────┬──────────────────────────────────┬───────────┤
│ 調色盤│                                  │ 屬性        │
│（依工具│           3D 場景                │（選中的東西  │
│ 切換）│      （格線、區域、路徑、單位標示）   │ 的數值）     │
│      │                                  │           │
├──────┴──────────────────────────────────┴───────────┤
│ 狀態列：座標、坡度、物件數 / 上限、提示                         │
└─────────────────────────────────────────────────────┘
```

- 鏡頭：自由飛行（WASD＋右鍵轉、滾輪高度、F 對準選取），也可以切成俯視（正交）。
- 拖曳箭頭（TransformControls，模型庫已經在用），數值欄位直接輸入。
- 快捷鍵：Ctrl+Z／Y、Del、Ctrl+D 複製、G／R 移動旋轉、1～7 切工具、P 試玩。

### 7.2 平板

- 左側直排工具列、下方可收合的調色盤、右側可收合的屬性抽屜（`@media` 與 `body.touchDev`）。
- 鏡頭：單指拖曳＝平移（在空地）、雙指＝縮放與旋轉、雙指上下＝高度。
- 單指點物件＝選取，按住拖曳＝移動（貼地、吸附），旋轉用屬性抽屜的 90° 按鈕或旋轉環；拖曳箭頭放大。
- 筆刷：單指塗、半徑與強度用抽屜的滑桿。
- 文字輸入（台詞、名稱）用系統鍵盤；觸發器卡片清單放全螢幕面板。
- 1180×820 觸控與 1920×1080 都要截圖檢查；844×390 的入口顯示「請用電腦或平板編輯」。

### 7.3 試玩

- 「從頭試玩」：用目前的機甲整備，在出生點開始；「從這裡試玩」：從鏡頭指向的地點開始（觸發器照常從頭）。
- 試玩用和正式遊玩相同的流程（World＋單位＋觸發器），但 `this.editTest` 存在：暫停選單多「回編輯器」，不寫存檔、不給獎勵。回來時編輯狀態（鏡頭、選取、復原紀錄）保留。
- 試玩中可以開「除錯」：顯示觸發器的觸發紀錄、計數器數值、區域圈。

### 7.4 驗證與上傳前通關

- 存檔時檢查：至少一個出生點、出生點不在虛空／牆裡、巡邏路徑可以走（坡度與障礙物，粗略）、觸發器引用的群組／區域存在、有可以達成的結束條件。
- **上傳到伺服器前必須由作者自己通關一次**（瑪利歐創作家的做法），避免分享打不完的關卡；通關紀錄（時間、機甲）一起上傳。

## 8. 存檔與分享

### 8.1 檔案格式

```js
{
  format: 'rubicon-level', v: 1, gen: '10.1',   // 格式版本、產生底圖的遊戲版本
  id: '…',               // 建立時隨機產生，改名不變
  name, desc, author,     // 文字一律在顯示時 escHtml
  created, updated,
  thumb: 'data:image/jpeg;base64,…',   // 256×144 縮圖（編輯器截圖）
  base: { theme, variant, seed, blank: false, props: 'all' | 'big' | 'none',
          tod, weather, size, zone: { x0, x1, z0, z1 } | 'full' | 'long' | 'arena', level: 5 },
  terrain: { cells: 92, h: '<base64 Int16>', water: null },
  removed: [{ kind, x, z }],
  props: [{ id: 'container', x, y, z, r: 0..3 | yaw, p: { w, h, d }, hp, tag }],
  marks: [{ k: 'spawn' | 'cache' | 'supply' | 'term' | 'exit' | 'target' | 'spawnpt', x, y, z, yaw, … }],
  paths: [{ id, name, pts: [[x, z, wait]], loop: true, y: null }],
  areas: [{ id, name, shape: 'box' | 'circle', x, z, w, d, r, yaw, color }],
  groups: [{ id, name, color }],
  units: [{ type, kind: 'enemy' | 'ace' | 'boss' | 'ally', x, z, yaw, group, beh: { k, path, r, back }, at: 'start' | 'trigger', k: 1 }],
  counters: [{ id, name, v: 0 }],
  triggers: [{ id, name, on: true, once: true, ev: {…}, cond: [...], act: [...] }],
  segs: null,     // 第 3 期：多段出擊
  clear: { by: 'author', t: 312, asm: {…} } | null,
}
```

- 讀檔一律經過 `sanitizeLevel`：限制數量、範圍（座標在 `limOut` 內）、只接受認得的物件／敵人 id、字串長度（名稱 40、台詞 120 字）；不認得的項目略過並提示。
- 格式升級寫成 `migrateLevel(v1 → v2 …)`，舊檔一定讀得進來。
- 大小上限 2 MB（一般關卡約 50～200 KB）。

### 8.2 本機

- 獨立的 IndexedDB `rubicon-levels`（不碰存檔與模型庫的資料庫）：`levels`（鍵 id）＋自動存檔（每 30 秒與試玩前）。
- 匯出／匯入 `.rubicon-level`（就是上面的 JSON）。

### 8.3 伺服器

- `server-models/levels/<id>.json`＋`index.json`（名稱、作者、說明、縮圖、主題、人數建議、通關時間、上傳時間、遊玩次數、通關次數）。
- API：`GET /api/levels`（清單，不含內容）、`GET /api/levels/<id>`、`PUT /api/levels/<id>`（需要作者金鑰）、`DELETE /api/levels/<id>`（需要作者金鑰）、`POST /api/levels/<id>/play`（遊玩／通關次數）。
- 作者金鑰：瀏覽器第一次上傳時隨機產生（localStorage `rubicon_author`），伺服器存它的雜湊；只有同一把金鑰能覆寫、刪除（不同於渲染風格的「任何人都能刪」，因為關卡是作品）。伺服器控制台可以刪任何關卡。
- 遊戲裡的「伺服器上的關卡」：清單（縮圖、名稱、作者、主題、通關率）、排序（最新／最多人玩）、搜尋、下載到本機、直接遊玩。

## 9. 多人

- 大廳的房間模式多一個「自訂關卡」：房主選關卡（本機或伺服器上的），大廳顯示名稱、縮圖、建議人數。
- 開局：伺服器網址時房主送關卡 id＋內容雜湊，客機從伺服器下載（和模型組 `RemoteSets` 同樣的方式）；直接開檔（PeerJS）時把關卡 JSON 分塊附在開局訊息裡。
- 客機用同一份關卡資料建 World（高度圖、物件、機能物件），所以地圖一致；單位、觸發器只在房主跑，客機照現有快照與事件顯示。
- 新增同步：目標文字、倒數、顯示中的區域圈、出口開啟（快照 `mis` 的 `lvl` 欄位）；觸發器狀態（啟用、已觸發、計數器、延遲中的動作、群組成員）隨快照低頻同步，**房主遷移**時新房主從這份狀態接手（延遲中的動作照剩餘時間繼續）。
- 提高 `NET_VERSION`。

## 10. 實作分期

| 期 | 內容 |
|---|---|
| **E1 基礎＋分享＋多人** | 關卡格式與 `sanitizeLevel`；World 讀關卡（高度圖、物件、機能物件）；可擺放物件表（第一批約 40 種）；編輯器畫面（電腦＋平板）：底圖、地形筆刷、物件擺放、出生點、單位擺放與行為（進攻／守住／警戒／巡邏）、路徑；復原重做；試玩；本機存檔、匯出匯入；伺服器 API（上傳需通關、作者金鑰、清單）；關卡選單；多人房間模式「自訂關卡」與同步；冒煙測試 |
| **E2 觸發器** | 區域、群組、計數器；觸發器卡片編輯器；全部事件／條件／動作；目標文字、倒數、出口、成功／失敗；生成點與增援（邊緣、空降、預告）；試玩除錯面板；觸發器狀態的同步與房主遷移；補給箱、補給台、資料終端、目標設施、撤退、護送車隊 |
| **E3 自製出擊與完善** | 多段出擊（轉場、帶入）；Boss 放置的細節（型態事件）；物件表補齊所有主題；陣列複製、對齊工具；伺服器清單的排序搜尋、遊玩／通關統計；範例關卡 3～5 個（教學用） |

每期照主線的流程：做完、測完（冒煙測試加編輯器的項目：擺放、存讀、試玩、上傳、多人兩分頁玩同一關），build＋commit＋push。

## 11. 待決事項

1. **獎勵**：自訂關卡給不給 COAM、駕駛員經驗、熟練度？（建議：不給 COAM 與經驗，只給熟練度與通關紀錄；否則自己做一關放滿弱敵就能刷）
2. **可用的敵人**：Boss、宿敵 AC、主線專屬敵人是否全部開放，還是只開放存檔裡遇過的？（建議：全部開放，創作自由度比較重要）
3. **伺服器的關卡權限**：只有作者能覆寫、刪除（建議），還是像渲染風格一樣任何人都可以？
4. **關卡等級**：由作者固定（建議，難度才穩定），還是跟著玩家的等級縮放？多人人數一律照 `enemyScale` 加成。
